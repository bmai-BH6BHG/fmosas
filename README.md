# fmosas — FMO 对讲系统 · 分系统（区域注册节点）

分系统是 FMO 对讲系统的**区域注册节点**，部署在各地区/机构的服务器上，为 APP 用户提供
注册、登录、心跳上报服务，并作为 **SAS 认证服务**（Ed25519 证书链）与**分布式同步节点**
与总系统及其他分系统协同。

FUS 现在由四个组件组成，各管一段、互不越界：

| 组件 | 管什么 | 页面 |
|------|--------|------|
| **SAS** | 身份是否可信（Ed25519 证书链、签发与吊销） | `/admin/sas` |
| **FAS** | 认证过程与审计（谁在什么时候通过/被拒） | `/admin/fus` |
| **互联桥接** | 消息如何互通（集群内多站语音中继） | `/admin/bridge` |
| **UDAC** | 已认证的实体**现在还能不能继续信、这一刻能做什么** | `/admin/udac` |

## 一键部署（推荐）

Linux / 群晖 DSM，一条命令，全自动（下载 → SHA256 校验 → 装依赖 → 生成配置 → 注册开机自启 → 自检）：

```bash
curl -fsSL https://github.com/bmai-BH6BHG/fmosas/releases/latest/download/install.sh | sudo bash
```

卸载（默认保留数据库 / CA / 上传图片）：

```bash
curl -fsSL https://github.com/bmai-BH6BHG/fmosas/releases/latest/download/uninstall.sh | sudo bash
```

彻底删除（含数据，删除前会校验目录）：

```bash
curl -fsSL https://github.com/bmai-BH6BHG/fmosas/releases/latest/download/uninstall.sh | sudo bash -s -- --purge
```

## UDAC：统一动态授权与信任控制中心 ★

SAS 判完「**身份可信**」就结束了，但身份可信不等于"现在这一刻还能继续信"：证书可能刚被吊销、
这台机器凌晨三点突然开始狂发消息、它跟我们之间的桥接丢包 30%……**UDAC 就是管这一段的**：
只读消费 SAS 的身份/证书状态与桥接健康度、音质，输出 **0–100 信任分**与**动态授权决策**。

页面：`http://<内网IP>:35929/admin/udac`（**只在内网，勿映射公网**）

### 三个部分

| 部分 | 作用 |
|------|------|
| **信任评分** `udac-trust-score` | 0–100 多维加权：身份 30% / 行为 25% / 桥接健康 15% / 音质 10% / 上下文 / 数据。含 7 天冷启动观察期与历史信任衰减（半衰期 24h） |
| **策略引擎** `udac-policy`（PDP） | 版本化「策略即代码」（JSON 结构化条件：`trust_min` / `hour_from` / `hour_to` / `scope`，**不 eval 任意表达式**）；支持**灰度发布 / 提升 / 回滚 / 仿真试运行** |
| **执行点** `udac-pep`（PEP） | 挂在 `/auth` 认证路径上：SAS 放行 → 信任评分 → 策略评估 → 与信任分阈值表**取更严者** → 审计 |

动作从宽到严：`allow` → `rate_limit` → `degrade` → `step_up` → `disconnect` → `quarantine` → `deny`。

* `deny` / `disconnect` / `quarantine`：**直接拒绝新接入**；
* 其余动作通过 `client_attrs`（`udac_action` / `udac_score`）交给 EMQX 限权；
* **已建立的会话不会被中断**（不给现网通话"突然掉线"）；
* 决策与事件只追加落库（`udac.db`），可回放追溯；原始认证审计仍归 FAS。

### 直通：这些接入不评分、直接通过 ★

有几类接入**已经在别处验证过了**，再拿"证书记录 / 吊销 / 冷启动 / 时段"去给它们扣分降权
只会帮倒忙 —— 实测给 APP 账号算成 48–52 分判 `step_up`、给桥接判 `rate_limit`（桥接还因此
连不上）。现在它们**直接放行、不参与评分**，决策里带「**直通**」标记：

| 直通类型 | 判据 | 为什么 |
|----------|------|--------|
| **APP 接入** | `app_verified=1`（APP 私钥 Ed25519 签名校验通过） | 已经过 SAS 身份 + APP 签名两道 |
| **APP 接入（第二次）** | clientid 形如 `FMO-<呼号>-<uid>-<随机>` 且 SAS 身份已通过 | 同一个 APP 会**接入两次**（先 `user`、再 `super`），其中 **`super` 那次不带签名**（`app_verified=0(none)`）—— 只凭签名认不出来，会被扣成 48 分判 `step_up` |
| **内部客户端** | `app_exempt=1`（面板 / 服务账号，豁免 APP 签名） | 属信任豁免的内部客户端 |
| **MQTT 互联桥接** | clientid `FMO-BRIDGE-*` 或服务呼号 `SERVER` | FUS 内部组件之间的语音互通，身份已由证书链 + 集群名片双重校验；一旦被 fail-closed 拒掉，表现就是"桥接连不上" |

**普通用户仍然照常评分与策略门控**（没有被顺手放过）：例如没有证书记录的呼号会拿到
`rate_limit`，策略命中该拒的照拒。

### 性能：别让「风控」变成「卡顿」★

UDAC 挂在认证主链路上，它慢一点就是全局慢。三处专门设计，都是踩过坑之后加的：

* **`udac.db` 用 WAL**（`journal_mode=WAL` + `busy_timeout` + `synchronous=NORMAL`）：
  认证路径每次连接都要写决策/事件，回滚日志模式下"写"会**锁整库**、所有读被堵住 ——
  实测 UDAC 接口 2 秒、排行 **60 秒超时**、管理页整片卡死、数据加载不出来；
* **排行读快照**：`ranking()` 默认**不重算**，只读 `trust_snapshot`；快照由后台线程每 5 分钟刷新
  一次（以前页面每几秒请求一次就把几百个呼号全量重算一遍）；
* **认证路径给 UDAC 加硬超时（0.45 秒）**：UDAC 卡住时按"本次未参与"继续，**绝不拖住 `/auth`**
  —— 否则 EMQX 等不到认证响应就会判连接失败，现象是桥接 `CONNACK 超时或非法`、老是连不上。

修复前后实测（同一台 NAS）：

| 接口 | 修复前 | 修复后 |
|------|--------|--------|
| `/api/udac/ranking` | **60 秒超时** | 2 ms |
| `/api/udac/status` | 2041 ms | 2.5 ms |
| `/api/udac/decisions` | 2682 ms | 3.6 ms |
| UDAC 页一次完整刷新（5 个接口） | **>60 秒** | **24.5 ms** |
| 本机 broker 连接 | 反复 `CONNACK 超时`（`local_state=error`） | `connected` |

### 界面

* **概览**：决策数、决策延迟 P99、信任等级分布、桥接/音质输入、最近一次全量证书扫描；
* **台站信任排行**：本机视角的 0–100 分排行（读快照，毫秒级）；
* **最近决策**：时间 / 呼号 / 动作 / 信任分 / 延迟 / 策略版本 / 原因；**带「直通」标记的就是不评分的那几类**；
* **策略管理**：看当前版本、发布新版本、灰度、提升、回滚、仿真试运行；
* **事件流**：`udac.*` 只追加事件（决策、排行重算、全量扫描触发…）。

### 接口

| 接口 | 说明 |
|------|------|
| `GET /api/udac/status` | 概览：决策数、P99、等级分布、桥接/音质输入 |
| `GET /api/udac/ranking?limit=` | 台站信任排行（读快照） |
| `GET /api/udac/decisions?limit=` | 决策审计（`exempt=1` 即「直通」） |
| `GET /api/udac/events?limit=` | 只追加事件流 |
| `GET /api/udac/policy` | 当前策略 + 所有版本 |
| `POST /api/udac/policy` | 发布策略版本（可指定灰度百分比） |
| `POST /api/udac/policy/promote` / `/rollback` | 灰度提升 / 回滚 |
| `POST /api/udac/simulate` | 策略试运行（**不写审计**） |

本机排行还会**随同步上报给总系统**，汇总成**全局台站信任排行**；总系统下发的全量扫描事件
也会喂给本机 UDAC 中心。

### UDAC 排障速查

| 现象 | 原因 / 处理 |
|------|-------------|
| UDAC 页卡、数据加载不出来 | 多半是 `udac.db` 落回**回滚日志**模式、或排行在全量重算。确认 `/opt/fmo-subsystem/udac.db-wal` 存在，`PRAGMA journal_mode` 应为 `wal` |
| 桥接显示 `CONNACK 超时或非法` / 连不上 | UDAC 拖住了 `/auth`。看日志有无 `UDAC 决策超时`；新版应有 0.45 秒硬超时兜底，且桥接本身走「直通」 |
| APP 账号被 `step_up`、或只有 50 分左右 | 该账号被当成普通用户评分了。升级到含「直通」的版本后，决策里应带「直通」 |
| 决策里全是 `rate_limit`、原因"无该呼号证书记录" | 评分拿不到该呼号的证书。若是 APP/服务账号，本应走直通；若是普通用户，说明它的证书确实不在 SAS 里 |
| 想收紧直通范围 | 直通按"APP 签名 / APP clientid 形态 / 内部豁免 / 桥接"四类判定，必要时可只保留"签名"那一类 |

## 互联桥接与集群（多站语音互通）

加入**同一个集群**的分系统之间会自动发现、互相校验身份、互为语音中继（**无主节点**，
任意一条链路断了其它链路照常工作）。不需要逐个添加服务器。

* **集群由总系统创建**（总系统管理页 →「集群管理」，像建群组一样），
  各分系统在**自己的**「互联桥接」页选一个加入；
* 原本那套全局互联原样保留为 **「主集群」**（默认、不可改名/删除；没选过的分系统都在里面）
  → **升级后什么都不选，行为与以前完全一致**；
* 只有**同一个集群内**的分系统之间才会建立链路；
* 成员身份是**互相校验**的（节点名片 + 与总服务器名册比对），不是谁自称就算；
* 成员的认定以"**是否真的加入**（桥接开关已打开）"为准，旧版本没有该功能的台站
  不会被算作成员、也不会出现在名册里。

### 本机 broker 地址（可选）

桥接要把本机语音放到**本机 broker** 上、对端连过来拉，所以它必须知道这个地址。
**默认自动使用**管理页「语音监控 → MQTT 地址配置」里那个地址（SAS 也是按它接入的），
不需要额外配置 —— "本机 broker 就在那个地址" 的机器什么都不用填。

**只有本机 broker 不在那个地址时**，才在「互联桥接」页的**本机 broker 地址**里单独填：

* 留空 = 回到管理页那个 MQTT 地址设置；
* 填了 = 只对桥接生效（不动监控/SAS 的地址）；
* 页面会显示当前地址**以及它是从哪来的**（`桥接设置` / `SAS/MQTT 地址设置` / `默认值`）；
* 改了地址立刻生效：桥接会断开重连到新地址，不用重启服务。

> 早期版本是在进程启动那一刻把地址取下来就固定了 —— 启动时还没配好、或后来在配置页
> 改了地址，桥接都还按旧值走（界面上显示的 broker 与实际不符、也就连不上）。
> 现在每次都是现算的。

挂公网隧道 / 反代的机器（本机走 `127.0.0.1`、对端要走隧道域名）还能单独填
**对外公布的本机 broker 地址**：它只决定"**别人该用哪个地址来连我的 broker**"，
会随同步上报给总系统、再出现在别人的名册里；留空则对端退回用名册里的 HTTP 主机名 + 1883。
**内网/回环地址不会被采用**（避免对端去连它自己的 `127.0.0.1`）。

### 延迟与音质（桥接页上的那几个数怎么读）★

桥接页的「健康度」里有几个数，**它们测的是不同东西**，别混：

| 指标 | 含义 | 参考值 |
|------|------|--------|
| **本机 broker 延迟** | 到本机 broker 的 PING 往返 | < 5 ms |
| **桥接延迟** | 对端语音帧**到达本机** → **重播出去**（含抖动缓冲）—— "听起来慢不慢"主要看它 | ≈ 抖动缓冲 + 30ms |
| **单向延迟估算** | 对端单程(RTT/2) + 抖动缓冲 + 重播排队 | < 350 ms 良好 |
| **链路抖动** | **同一段发言内**帧到达间隔的波动 | < 30 ms 为佳 |
| **疑似丢包** | 同一段发言内帧间隔骤增的比例 | < 1% |
| **音质 MOS** | 由抖动+丢包估算（取最差一条成员链路） | ≥ 3.5 良好 |
| **抖动缓冲** | 用来吸收网络抖动的缓冲时长（设置里可调） | 默认 80 ms |

**两个踩过的坑，已经修掉**：

* **静默被算成抖动/丢包**：早先的实现用"距上一帧的间隔"算抖动，于是
  「这次发言结束 → 20 秒后对方开口」这个**正常静默**被算成 20 秒的抖动，
  指标直接报成 `抖动 19608ms`、丢包率虚高、MOS 算成 1.0，还被 UDAC 拿去当桥接健康度
  给节点扣分。现在只在**同一次连续发言内**统计，静默会重置基线。
* **重播被读超时压住**：本机连接的读循环是"读一次包才排空一次重播队列"，
  默认 5 秒读超时会让"该 80ms 释放"的帧被压住几百毫秒到数秒。现在读超时 0.05s，
  重播按抖动缓冲准时释放（实测 79.5ms，峰值 129ms）。

另外：**迟到超过 2 秒的帧直接丢弃** —— 宁可断一下，也不要放几秒前的旧语音。

> 顺带修掉一个会**静默丢语音**的解析 bug：收包时若"包首部"与"包体"分两个 TCP 段到达，
> 旧实现已经把首部消费掉了，超时返回后包体被留在缓冲区 → 从此整个字节流解析错位，
> 后续的包全被当成垃圾丢掉。现在改成"凑齐一个完整包才消费缓冲区"，半包原样保留。

### 单向语音：我这边过得去，对面的声音过不来

几乎都是**对端 EMQX 的 ACL 没放行桥接主题**。桥接是"各自去订阅对方的语音主题"，
若对端 ACL 是收紧版（最后一条 `{deny, all}.`）、里面只放行了 `FMO/RAW`、`FMO/TELE`
这些老主题而**没有 `FMO/BRIDGE/#`**，我们订阅它的主题会被拒（`SUBACK=0x80`）
→ 拿不到它的集群名片，也收不到它的声音。

这条规则属于**部署时配的 EMQX 授权，不在代码里**，所以升级 FUS 补不上，
要在**对端那一台**上跑一次：

```bash
curl -fsSL https://github.com/bmai-BH6BHG/fmosas/releases/latest/download/fus-fix-acl.sh -o fus-fix-acl.sh
sudo bash fus-fix-acl.sh --check   # 先看现状，不改动
sudo bash fus-fix-acl.sh           # 修复：自动备份 → 在 deny-all 之前插入放行规则 → 重载 EMQX
```

脚本自动识别 docker / 原生两种 EMQX 安装，**已放行就不动**（幂等），
找不到配置文件时只打印手工步骤、绝不乱改。

### 排障速查

| 现象 | 原因 / 处理 |
|------|-------------|
| 对端显示 `rc=5 连接被拒绝（对端不认我方证书）` | 对端没把我们总系统下发的信任背书落进它的 `sas.db.trust_chain`（版本旧或同步停了）。用总系统的 `/api/trust/roots` 拿到我方根公钥，填进对端配置的 `trust.extraRootPubkeys`，或让它升级 |
| 对端显示 `SUBACK=0x80 / ACL 拒绝订阅` | 对端 ACL 没放行 `FMO/BRIDGE/#` → 跑上面的 `fus-fix-acl.sh` |
| 对端显示 `对方未加入集群` | 对端桥接没开（在它自己的桥接页点「加入集群」） |
| 名册里少了某台 | 那台没加入、或长时间没上报（僵尸登记会被自动剔除）；让它加入/恢复上报即自动回来 |
| 界面上"已加入"但一直没声音 | 看对端的 `rx_frames` 是否在涨；涨说明在收它的语音 |
| 界面顶部"已加入集群"、本机那行却是"未加入" | 旧版把"总开关关闭"和"还没开始连"显示成同一句话。新版：总开关开着就只显示 连接中/已连接/连接失败；"未加入（桥接总开关已关闭）"才是真的没加入 |
| 本机 broker 反复连不上（`CONNACK 超时`） | 见上面 UDAC 排障：UDAC 拖住认证会让 EMQX 判连接失败 |

## 上报地址自动化（APP 该连哪台，机器自己知道）★

以前要在管理页**手填**"上报地址"、点保存、还得记得上传总系统；填错或忘改，APP 与对端就
连到错的地方（本机 `127.0.0.1` 这种内网地址尤其致命）。现在**全自动**：

* 分系统向总系统问一句"**你看到的我是什么 IP**"（`GET /api/myip`），**以它为准** ——
  不需要任何第三方服务，也不受本机多网卡/内网地址干扰；
* 拿到之后**直接写进配置并立即上报总系统**，没有"填 → 保存 → 上传"三步；
* 后台线程**每 10 分钟自动扫一次**，而且**地址真的变了才写盘/上报**（幂等，不折腾）；
* **只有公网 IP 会被采用**：两端都校验，内网/回环地址一律不采信
  （踩过：走 `127.0.0.1` 去问，总系统看到的当然是 `127.0.0.1`，写进上报地址就把 APP 和对端全带偏了）；
* 总系统这条路不通时，才退回外部回显服务。

「语音监控」页有「**上报地址（自动）**」面板：显示当前地址、可一键重扫；
也可直接调 `POST /api/config/auto-address`。

### 管理页这一版的变化

* **注册系统上移总系统**：分系统侧的「注册系统」页与 APP 登录地址配置**已移除**，
  用户注册/管理统一在**总系统**做（分系统只保留 SAS / FAS / 桥接 / UDAC / 语音监控）；
* **MQTT 地址配置移到「语音监控」**：地址的生效位置没变（SAS/监控都按它接入），只是入口挪了；
* **FMO 台站扫描上移总系统**：分系统的台站页（`/admin/stations`）**已移除**，扫描与汇总在总系统做；
* **上报地址自动扫描**：见上一节；
* **📼 录音库**：语音监控页新增录音库（翻查 / 连续回听 / 整段导出 / 删除区间），
  默认**永久保留**，见上面的「语音录音库」一节。

## 语音录音库（一直在录 · 随时回听）★

从**服务启动那一刻**起，本机收到的语音就在往库里写 —— 包括**互联桥接从别的节点转来的**声音。
一次连续发言存成"一段"，带时间、呼号、时长、编码、来源，页面上可以随时翻查回听。

**入口**：管理页 →「语音监控」→「📼 录音库」（`http://<内网IP>:35929/admin/sas`）

| 功能 | 说明 |
|------|------|
| 按日期翻查 | 选日期 +（可选）呼号 + 来源（全部 / 本机收的 / 桥接转来的），回车即查 |
| 24 小时分布条 | 一眼看出"哪段时间有声音"，点某小时就只看那一段，再点一次取消 |
| 逐条回听 | 每行「▶ 播放」，用的就是瀑布图那套播放器（音量、"正在播放"一致） |
| 连续回听 | 「▶ 顺序播放本区间」按时间把区间内的段一段段放完，可随时「■ 停止播放」 |
| 单条下载 | 每行「⬇ 下载」得到标准 `.ogg`（Ogg/Opus），任何播放器都能放 |
| 整段导出 | 「⬇ 导出本区间」把区间内所有段**合并成一个 Ogg 文件**（段间自动补 1.2 秒停顿），一次听完/存档/转发 |
| 删除区间 | 「🗑 删除本区间」需在弹窗里**二次确认**（防误删） |

**保留策略（不会再"过几秒就没了"）**：

| 配置（`config.json` → `monitor`） | 默认 | 说明 |
|---|---|---|
| `retention_days` | **0 = 永久保留** | 从部署那一刻开始的录音一直留着；设成 N 则只留 N 天 |
| `max_db_mb` | 2048 | 容量上限：语音总量超了就删**最老**的段（保护磁盘，不会把服务器写满） |
| `beacon_retention_days` | 30 | 信标（FMO/TELE）单独保留天数 —— 它是元数据、掉得快，不跟语音一起永久堆 |

页面顶部直接显示：全库多少段 / 总时长 / 占用大小 / 最早录音时间 / 当前保留策略。

> 早期版本默认只留 3 天，而且页面上基本只能"听实时的"、过去的翻不出来 —— 这两个都改了。
> 段与段之间的停顿用 Ogg 的 granule 跳变表示（合法且播放器会自动补静音），
> 不伪造静音包 —— 伪造包在部分解码器上会直接报错。

**接口**（内网管理口）：

| 接口 | 说明 |
|------|------|
| `GET /api/monitor/recordings?from=&to=&callsign=&origin=&limit=&offset=` | 分页列表（只回元数据，不含音频，可一次列很多） |
| `GET /api/monitor/timeline?from=&to=&bucket=3600` | 时间轴：每桶的段数与时长 |
| `GET /api/monitor/rec_stats` | 总览（总量 + 保留策略）+ 区间统计 |
| `GET /api/monitor/audio?id=` | 单段音频（Opus 自动封装为 Ogg，可直接播放/下载） |
| `GET /api/monitor/export?from=&to=` | 区间合并导出成一个 Ogg 文件 |
| `POST /api/monitor/delete_range` | 删除区间（body 需带 `confirm: true`） |

`origin` 取值：不传 = 全部；`local` = 只看本机收的；`bridge` = 只看桥接转来的。

## 安全

* `ca/ca_private.json`（CA 私钥）、`*_users.db`、`*_sas.db`、`voice.db`、`udac.db`、审计库、`uploads/`
  均为运行时敏感数据，已在 `.gitignore` 排除，发布包中也不包含。
* 管理端口（公网口 + 1）只在内网使用，不要做端口映射（UDAC / 桥接 / SAS 页都在这里）。
* APP 私钥 `APP_SEED` **只烧进 APP**：不要写进 `config.json`、不要上传服务器、
  **不要贴进代码/文档/工单**。服务端只保存对应的公钥（`dmrid.app_pubkey`）。
  本仓库不再内置任何 APP 密钥，也不在发版包里带 `tests/`，打包时会扫描密钥字面量。
* UDAC 的「直通」只针对**已经在别处完成验证**的接入（APP 签名 / APP 客户端 / 内部豁免 / MQTT 桥接），
  普通用户仍走完整的信任评分与策略门控；如需收紧，见上面的排障表。
